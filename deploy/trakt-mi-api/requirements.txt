# trakt-mi-api — the App Service runtime dependency contract.
#
# This is the file Oryx builds when the API is deployed, because the deploy
# workflow stages an artefact whose ROOT requirements.txt is this file. The repo
# root requirements.txt is the *repository's* dependency set (Function App,
# Streamlit, the ESMA delivery engine, mail); handing that to Oryx made the App
# Service build install scikit-learn, scipy, streamlit and friends on every
# deploy — none of which the MI API imports.
#
# Every entry below is justified by an import reachable from
# ``mi_agent_api.app``. tests/test_mi_api_appservice_packaging.py recomputes that
# import closure and fails if this file drifts from it, so a new runtime
# dependency cannot be forgotten here and a stale one cannot linger unnoticed.
#
# Version specifiers are copied verbatim from the root requirements.txt so the
# two cannot resolve to different versions of the same library.

# --- Web server (startup.sh: gunicorn + uvicorn worker) ---
fastapi>=0.110
uvicorn[standard]>=0.27
gunicorn>=21.2
uvicorn-worker>=0.2          # gunicorn worker class (uvicorn_worker.UvicornWorker)
# Imported directly by mi_agent_api/app.py and copilot_actions.py (BaseModel,
# Field), so it belongs in the contract rather than being relied on as a FastAPI
# transitive. Deliberately unpinned: that is exactly how it resolves today, so
# declaring it changes nothing about which version the App Service installs.
pydantic

# --- Entra bearer-token validation ---
# copilot_auth.py, agent_auth.py, react_auth.py, teams_bot.py. [crypto] pulls the
# RS256 signature backend, without which every token check fails closed at 503.
